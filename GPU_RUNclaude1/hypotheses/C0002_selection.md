## 選択理由 — C0001 を潰した失敗様式を構成的に回避する

C0001 が `undecidable` に終わった最大の原因は、**エンドポイントの実現分母が事前に不明**だったこと
である。名目 130 単位に対し実現 `n_eff ≤ 88`（検証された下限なし）で、区間も検定力も
実際には行われていない推論を記述していた。

選んだ 2 件は、いずれも**実現分母が構成上既知**である。

- `H0001-R`: 80 system / 960 cell / 47,987 候補。**47,987/47,987 が `valid: true`、cell 失敗 0 件**
  （C0001 が確立した事実）。機会センサスを要しない
- `H0010`: 846 骨格クラス / 89,349 成分文字列の**全数分類**。標本ではない

したがって設計ブリーフ §6 の新しい常設設計要件「実現分母が事前に不明なエンドポイントは
機会センサスをゲート前提条件として事前登録する」は、**本サイクルでは該当しない**（要件を
満たすのではなく、そもそも該当しない設計を選んだ）。

## 相互に排他的であること

E2 と E3 は排他で、修正経路が完全に異なる（分布側の介入 対 探索予算・温度）。
**どちらに転んでも 1 つの分岐が閉じる**:

- E2 が支持 → いかなる現実的な予算増加も真値を浮上させない。`H0003`（温度・ビーム掃引）は永久に閉じる
- E2 が棄却 → E3 が主説明に昇格し、`H0003` が**証拠に基づいて**初めて発火する

`H0010` も同様に両向きで情報がある。棄却されれば「欠落は周辺水準で既に起きている」ことになり、
C0003 の修正は結合構造という難問を立てずサポート・語彙側で足りる。

## 凍結前に必ず解決すべき 2 件（Stage 3 の methodologist への申し送り）

**これらは C0001 の結果を救済する変更ではない。計器を測定可能にする変更である。**

1. **CRITICAL-R3 — `lp_sel` の定義。** 保存データは `beam_type = "sampling"` であり、
   スコア順に並べ替えるのは `model_wrapper.py:107-113` の `"search"` 分岐のみ。
   `candidate_index == 0` は選択結果ではなく標本順である。これを `lp_sel` に使うと
   `search_error_system_rate` が 1 に膨らみ **E3 を捏造する**。
   **アーム分離が必須**:
   - **アーム A**: 保存済み sampling 候補の最大 `lp_best` に対し `sb_best` を測る
   - **アーム B**: `beam_type = "search"` で再デコードし、探索自身の出力に対し `sb_sel` を測る
   - **(B) は候補集合が変わるので (A) の代替ではない。別実験として宣言し事前登録すること。**
   - アーム B を本サイクルに含めるかは、Stage 2 文献（`literature/C0002_literature.md`、
     設問 2）が Stahlberg–Byrne 指標に対して何を許すかに依存する。**文献の回答前に凍結しない。**
   - 併せて契約引用の欠陥: v2.1 §8.3 は `gpu_run5_selection.py:11` を「凍結された選択規則」と
     引用するが、当該関数 `formula_selection_key` は run 横断のモデル選択スコアラであって
     セルごとの選択器ではない。C0002 では正しい参照に差し替える
2. **`could_not_evaluate` を決定論的予算で再定義する。** 実時間 `SIGALRM`（10.0 秒）では、
   同一入力・同一上限で **101,963 件中 14 件**のラベルが双方向に揺れ、率が再現しない（9 対 7、
   共通 1 件）。ノード数・演算回数など負荷と SymPy キャッシュ状態に依存しない量に置き換える。
   なお C0001 において **M3 の値そのものは 101,963 件すべてで一致**したため、
   `k_gains = 0` はこの問題の影響を受けていない（この点を混同しないこと）。
