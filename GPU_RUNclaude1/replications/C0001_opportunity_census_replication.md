## 1. 要旨

本追試は「凍結マッチャ M0 と寛容マッチャ M3 が実三つ組 101,963 件すべてで点ごとに一致した」
というサイクルの見出し主張について、その**証拠価値**を決める量（M3 が M0 と異なる**機会**を
何回持ったか）を独立に測定した。結果は四つに分かれる。

1. **エンドポイント自体は完全に再現した。** 保存済み 101,963 件の M3 値を、別経路
   （同値類メモ化）・別プロセス・別アーティファクトパスで全件再計算し、**不一致 0 件**。
   PC4 も凍結値どおり（`eligible 170/170`, `M0 40/170`, `M3 140/170`, `gain 100`,
   `gain_H 100`, `gain_L 0`, 寄与ファミリ 6）に再現した。

2. **レビューの二つのスクリーンは数値まで完全に再現した。** M3-necessary スクリーンは
   **5,851 / 77,983**・**88 / 130**、operator-multiset スクリーンは **187 / 77,983**・
   **9 / 130**。派生量 `Wilson(0, 9) = [0, 0.299145]`、`p = 0.0525` での検定力 **0.38452**、
   `n_eff = 130` での **0.99910** もすべて一致する。

3. **しかし operator-multiset スクリーンは M3 に対して無効である。** サイクル自身の陽性
   対照 PC4 が与える**唯一の非循環な H 層陽性集合（100 件の実 gain）に対し、このスクリーンは
   100 / 100 を誤って除外する**。したがってブラケット `[9, 88]` の下端 9 は成立せず、
   130 中 121 という数字も成立しない。妥当なのは**上限 $`n_{\mathrm{eff}} \le 88`$ のみ**であり、
   下限は存在しない。下限が無いことは `CRITICAL-R2` の結論（結論をブロックする）を
   **弱めるのではなく、むしろ確定させる**：`n_eff` は 0 まで許され、その場合 Wilson は
   `[0, 1]` となり凍結許容域 `[0.053, 0.629]` は一切排除されない。

4. **レビューの残余懸念のうち二つは解決した。** `MAJOR-R1`（`bool(None)` の穴）は
   2,191 類ペアの全数探査で `equals_NONE` **0 / 101,963** と確定し、境界が約 265 件から
   厳密な 0 に締まった。`could_not_evaluate` 9 件は 9 / 9 を数値反証した。一方
   `CRITICAL-R1`（壁時計依存）は再現し、`match_outcome_m3` のラベルは 101,963 件中
   14 件で両方向に食い違った。**M3 の値は全件一致**するので `K = 0` は無影響である。

さらに、レビューが持っていない一段強い測定を得た。**実現した骨格語彙全体の上で、M3 の
等価判定は実質的に恒等写像である**（879 骨格類 → M3 同値類 **877**、統合はわずか 2 件で
いずれも候補どうし）。すなわち M0 と M3 の対比は、強さのほとんど等しい二つの構文正規化の
対比に縮退していた。

### 3.3 M3 同値構造 — レビューが持たない測定

M3 の判定は定数畳み込み骨格の対のみに依存するので、879 類の上での M3 関係を数値指紋
（シード `77771`、`mpmath.mp.dps = 40`、10 点）でバケット化し、各バケット内で凍結判定を

| 量 | 値 |
|---|---|
| 骨格類 | 879 |
| 指紋バケット | 877（`BAD`/`ERR` 指紋 0） |
| バケット内で実行した凍結 M3 判定 | 2（うち等号成立 2） |

統合は 2 件のみで、いずれも**候補どうし**の符号対称変形である。

```

c*(c + x_1)**2 + c*(c*x_1 - 1)**2  ==  c*(c - x_1)**2 + c*(c*x_1 + 1)**2

**この語彙の上で M3 は「骨格類が文字どおり同一か」以上の何も判定していない。**
定数畳み込みと SymPy 等価判定という M3 固有の機構が働いたのは、真値と候補の対では
**0 回**である。これは循環ではない測定であり、「M0 と M3 の一致」がなぜ情報を持たないかの
機構的な説明を与える。

### 3.5 スクリーンの妥当性検証 — ここが本追試の核心

**(a) 2,235 件の実現マッチによる検証は循環している。** 実現した M3 マッチ 2,235 件は
**全件が M0 = 1**（§3.1 の同時分布）。M0 に必要なスクリーンは、この集合に対して
偽陰性 0 を**構成上必ず**返す。したがって「偽陰性 0」は観測ではなく定理であり、
M3 に対するスクリーンの妥当性について**一切の情報を持たない**。
同じ理由で、H 専用スクリーン（S1 など）はこの集合ではまったく検証できない
（2,235 件は全て L にあり、L の真値には変数分母が無いため S1 の適用域外。S1 の
「偽陰性 2,235」はこの適用域外に由来し、欠陥ではない）。

**(b) 非循環な陽性集合は PC4 のみである。** PC4 は各真値成分 `T_i` を
`R_i = str(sympy.together(sympify(T_i)))` へ書き換え、合成候補として
主要測定と同一のコード経路で採点する。本追試での再現は凍結値と完全一致した。

| PC4 | 凍結 v2.1 Q12 / 保存 `partA_controls.json` | 本追試 |
|---|---|---|
| eligible | 170 / 170 | **170 / 170** |
| M0 | 40 / 170 | **40 / 170** |
| M3 | 140 / 170 | **140 / 170** |
| gain | 100 | **100** |
| gain 層 H | 100 | **100** |
| gain 層 L | 0 | **0** |
| 寄与ファミリ | 6（R02 R03 R04 R06 R07 R08） | **6（R02 R03 R04 R06 R07 R08）** |

この **100 件は H 層における実際の M3-over-M0 gain** であり、各スクリーンを検証できる
唯一の非循環集合である。結果は決定的である。

| スクリーン | 100 件の H gain に対する偽陰性 | 判定 |
|---|---|---|

```

formula_metrics(...)["component_exponent_aware_skeleton_exact"]                  = [0.0]

```

これは **M3 = 1、M0 = 0 の真の gain** でありながら演算子多重集合が一致しない。すなわち
多重集合スクリーンは、まさに主要エンドポイントが数えようとしている事象を取り落とす。

### 3.7 付随して確認した事実

**層定義の健全性。** 凍結 H / L 割り当てを、定数畳み込み骨格の約分後分母という
書き換え不変な定義と照合した結果は `(H, True) 130`、`(L, False) 40` の**完全一致**。
`sha256_of_component_assignment = 29a9b0f14069f59909261c7a79dcd49116a069b6a11d209ab9eb31a9a13bd546`。

**規則 R1 の罠は実在する（確認済み）。** 保存済み
`phase3/cells/*.json:true_structure.exponent_aware_skeleton` は
`classify_formula(true_prefix)` と一致し、`classify_formula(true_formula)` とは
**検査した 80 / 80 システムで相違する**。例（`R01_validation_d101_000`）：

```
stored     : add,add,CONST,mul,mul,CONST,inv,add,CONST,x_0,x_0,neg,mul,CONST,x_0
from infix : add,add,CONST,mul,CONST,x_0,mul,mul,CONST,inv,add,CONST,x_0,x_0
from prefix: add,add,CONST,mul,mul,CONST,inv,add,CONST,x_0,x_0,neg,mul,CONST,x_0

## 6. `_timed_equals` の `bool(None)` 穴

`equation_metrics.py:62-65` の `_timed_equals` は `bool(a.equals(b))` であり、
`sympy.Expr.equals` は `True` / `False` / **`None`** を返しうる。`bool(None)` は `False` なので、
**未決の比較が `failure_reason: None` の決定済み非一致として記録され**、
`_outcome_for_skeleton` により `proved_different` に分類され、
`could_not_evaluate_rate` の分子から除外される。方向は
`proved_different` を膨らませ `could_not_evaluate` を縮める、
すなわち null 型エンドポイントに対して**反保守的**である。穴の存在は確認した。

レビューは 60 セル × 12 候補 = 1,476 三つ組の標本で `diff_zero` 11 /
`equals_False` 1,465 / `equals_None` **0** を測り、`0 / 1,476` の Wilson から
101,963 件中最大約 265 件までを許すと述べている。本追試は標本ではなく
**実現した相異なる骨格類ペアの全体**に対して素の `.equals` 戻り値を記録する経路を
組んだ（`step5_pairs.py`）。M3 の判定は骨格類ペアのみの関数なので、全ペアを覆えば
101,963 件すべてを覆う。

測定設計上の注意を一つ記録する。**素の `.equals` を保護なしで呼ぶ探査は、この
コーパスでは完了しない。** 最初の実装は `_timed_equals`（10 秒保護つき）の後に
保護なしの `a.equals(b)` を追加で呼んでおり、2,191 ペアに対して 6 並列で約 25 分
経過しても終わらなかった（`step5_pairs.py`、打ち切り）。素の戻り値を測るには、
`_time_limit(SYMPY_OP_TIMEOUT_SEC)` の**内側**で `a.equals(b)` を 1 回だけ呼び、
`_SymTimeout` を `equals_timeout` として別に数える必要がある（`step17_equals.py`）。
`SYMPY_OP_TIMEOUT_SEC` は 10.0 のまま変更していない。
`MAJOR-R1` を「測定されたエンドポイント」に昇格させる将来の実装は、この保護を
省いてはならない。

### CRITICAL-1 — `CRITICAL-R2` の定量は失格。ただし結論は残る

レビュー §2.2(b) の operator-multiset スクリーンは、`n_eff` ブラケットの下端 9、

レビューが提示する妥当性根拠「2,235 件の実現マッチに偽陰性 0」は、
2,235 件が全件 `M0 = 1` でスクリーンが M0-necessary であるため**構成上の恒真**であり、
検証になっていない。

**帰結。** $`n_{\mathrm{eff}} \in [9, 88]`$、「130 中 121」、`Wilson(0, 9)`、検定力 0.38452 は
定量として撤回すべきである。妥当な定量は **$`n_{\mathrm{eff}} \le 88`$（上限のみ、下限なし）**、

（支持された結論をブロックする）は成立する。下限が無いという事実こそが、
どの区間も検定力も主張できない理由だからである。

### CRITICAL-2 — M3 は実現語彙上で骨格類の恒等判定に縮退していた

879 の定数畳み込み骨格類に対する M3 同値類は **877**。統合はわずか 2 件で、いずれも
候補どうしの符号対称変形であり、真値・候補の対では 1 件も無い（§3.3）。
すなわち M3 固有の機構（定数畳み込み＋SymPy 等価判定）は、このコーパスの
真値・候補比較において**一度も働いていない**。M0-vs-M3 の対比は、

これは循環でない測定であり、`CRITICAL-R2` の背後にある機構を与える。
**支持された E0 結論をブロックする。**

### MAJOR-1 — 実現マッチによるスクリーン検証は原理的に循環する

`gain` は `m0\_any = 0` を要求するので、実現した M3 マッチはすべて `M0 = 1` 側にある
（本コーパスでは 2,235 / 2,235）。したがって M0 に必要な任意のスクリーンは
この集合で偽陰性 0 を必ず返す。将来のサイクルでスクリーンや近傍指標を導入する場合、
**検証集合は PC4 型の合成陽性（`m3 = 1, m0 = 0`）でなければならない**。
本追試は S1 / S2 をこの方法で検証し、いずれも 0 / 100 で妥当と確認した。

### MAJOR-2 — 「121」と「9」が二重の意味を持ち、混同されやすい

`in_support` 交差表の 121（サポート内 H 成分）／9（サポート外 H 成分）と、
S3' スクリーンの 121（機会なし成分）／9（機会あり成分）は**別集合で濃度が一致するだけ**
である。レビュー §3 の「121 のうち 112 がサポート内」は内部的には整合するが、
基数 121 が失格したスクリーンに依存する。**訂正後の E1' 帰属**は次のとおり。

| 帰属 | 妥当なスクリーン S1 基準 | 類解像度（`K = 0` と同値、参考） |
|---|---|---|
| 機会なし H 成分 | 42 / 130 | 130 / 130 |
| うち E1'（サポート外） | **4** | **9** |
| うち E2 / E3 | **38** | **121** |

いずれの基準でも**主因は E1' ではなく E2 / E3** である。方向はレビューと一致する。

### MAJOR-3（レビュー懸念の格下げ） — `could_not_evaluate` 9 件はすべて解決した
