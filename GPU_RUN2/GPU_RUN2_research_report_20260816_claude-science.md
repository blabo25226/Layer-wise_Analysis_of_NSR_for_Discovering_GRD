## 1. 事実：実験設定

### 1.1 データ

Phase 1はGNW由来のHill型8族 G01–G08、計240 problem（族あたり30 variant）を生成した。
族の構造は次のとおりで、真の式は G01 を除きすべて**変数を分母に含む有理式**である
（seed101・noise 0.0 の主split test 48 problem で確認：G01 が 0/6、G02–G08 が 6/6）。

| 族 | 変数数 | 骨格の型 |
|---|---|---|
| G01 | 1 | 基底減衰 $\dot{x}_1 = a - a x_1$（線形） |
| G02, G03 | 2 | 単一制御因子のHill型 $\dfrac{-\alpha x_1 x_2^n + \alpha x_2^n + \beta}{\gamma x_2^n + 1}$ 系 |
| G04–G06 | 3 | 2活性化因子／活性化＋不活性化因子 |
| G07, G08 | 3 | 2モジュール混合 |

- seed bundle 3個（data_seed 101 / 202 / 303、model_seed 0/1/2）× noise 2条件（0.0, 0.1）。
- 主split（`main`）は族内でvariantを分割する。構造holdout split（`structure_holdout`）は族単位で分割し、**G07・G08 は test にのみ出現**する。
- 主split test は 48 problem × 3 seed = 144 record／noise条件、構造holdout test は 60 problem × 3 seed = 180 record／noise条件。
- 演算子allowlistは add, sub, mul, div, 整数べき $2\!-\!5$, 定数のみ。sin/cos/tan/exp/log/sqrt/abs は全面禁止。分母margin $10^{-6}$。
- decode入力点は全手法・全条件で同一の80点に固定、性能評価は独立した点集合（学習範囲内 / 入力範囲外挿）で行う。

### 1.2 条件

Phase 5の5条件は次のとおり。層ランキングはvalidationのprobeで決定し、test前に凍結されている（`frozen_before_test: true`）。

## 5. 考察（事実からの解釈）

重大度順に述べる。各項目は §1–§4 の事実にのみ依拠する。

### 5.1 本runの主要な発見は「回復失敗の所在が特定できたこと」である

symbolic recoveryは主splitで最大 8.0%、構造holdoutで 0%、exact一致は全条件で0であった。
これはGPU_RUN1（全条件0）からの改善だが、回復はすべて**1変数線形族 G01 のみ**に集中している。
より重要なのは §4.2 の事実である：真の式の 87.5%（G02–G08 の全問題）が変数を分母に含む有理式であるのに、
NeSymReSは主split・構造holdoutの3,000件を超える有効式で**一度も変数分母の式を出していない**。

これは「回復率が低い」という量的問題ではなく、**探索が真の式のクラスに到達していない**という質的問題を示唆する。
`div` はallowlistに含まれ、decode時のtoken maskも有効（preflightの `decode_token_mask_active: true`）であるから、
禁止による排除ではない。DecoderLensの集計（§2.4）でも `div` が上位候補に現れる頻度は `sin`・`exp` の1/10以下であり、
事前学習分布が有理関数に確率質量をほとんど置いていない可能性と整合する。
PySRが同じ問題で 57.2% の有理式を出していることは、データ側が有理構造を要求していない可能性を弱める。

**推測**：GRD向けにNeSymReSを適応させる際の律速は、層の選び方でも学習量でもなく、
事前学習の式prior（sin/exp中心、有理式が希薄）と、Hill型ODEという対象クラスの不一致にある可能性が高い。
これはfine-tuning設計の問題であり、GPU_RUN3の主要課題として扱うべきである。

### 5.2 層別役割は「decoderに構造情報、encoderに系列情報」で複数手法が整合する

probe（decoderでテンプレート識別1.000・演算子数$R^2$≈0.95）、単一層FT（6条件すべてで事前学習を下回るのは `decoder_4` のみ）、
ablation・介入（decoder層が上限飽和）という3系統が、いずれも decoder 側に式構造の情報が集中することを支持する。
一方で次トークン正解率だけは encoder_4 が最高であり、encoder が入力系列の局所情報を保持していることと矛盾しない。
これは本runで**最も再現性の高い所見**である。

ただし限界が2つある。第一に、順位一致（§2.3）で単一層FT順が probe / ablation 順と**負**の関連を示す。
第二に、正規化contributionが全層NaNであるため、「どの層がどれだけ寄与するか」を定量比較する主指標が失われている。
現状で言えるのは順序の粗い一致までであり、「層寄与の定量的分解」はまだ得られていない。

### 5.3 「少数層FT ≈ 全層FT」は主splitでは成立していない

事前指定margin ±0.05 での判定（§3.3）は、上位層FT vs 全層FT が主splitの両noise条件で margin 内に収まらないことを示す。
これは差が大きいからではなく、**n=3 seedでは区間が広すぎるため**である（noise 0.0 で幅0.27）。
「同等」とは言えず、「差が検出できるほどのデータが無い」が正確な記述である。
GPU_RUN2 計画の期待（GPU_RUN1で観測された「margin内で同等」）は、本runでは再現されなかった。

一方、上位層FT vs 事前学習、上位層FT vs ランダム3層FT はすべて margin 内である。
すなわち**層ランキングの付加価値も、この検出力では示せていない**。ランダム3層との差は主split noise 0.0 で −0.0087 [−0.012, −0.005] と
統計的には0を外れるが、実務的意味を持つ大きさではない。

### 5.4 学習範囲内の改善と外挿の悪化はトレードオフになっている

学習範囲内では上位層FTが最良（主split noise 0.0 で 0.0339 対 事前学習 0.0533）だが、
入力範囲外挿では順序が完全に逆転し、**全条件で事前学習のままが最良**である
（主split noise 0.1: 事前学習 0.0516 対 上位1層FT 0.113、差 +0.0603 [+0.021, +0.100]）。
全層FTの外挿誤差は主splitで中央値 3.9–6.7 と2桁悪化する。

**推測**：5 epoch・240 problem規模のFTは、decode範囲内で数値を合わせる方向に働き、
式の大域的な形状（極限挙動）を悪化させている。低NMSEを成功指標に使うと、この劣化は見えない。
これは本プロジェクトの「数値精度と式回復を区別する」原則が実際に効いた事例である。

### 5.5 全層FTは未学習構造で式そのものを壊す

構造holdout test の有効式率は 0.711（noise 0.0）・0.672（noise 0.1）で、未学習族 G07 では 0.64 まで落ちる。
失敗事由の大半は `DisallowedPowerExponent`、すなわち許可外のべき指数を含む式の生成である。
`valid_nmse` だけを見れば全層FTは 0.0582 と悪くないが、これは**3割の失敗を除外した条件付き指標**であり、
failure考慮NMSE（0.0735）と有効式率を併記しなければ誤読を招く。

### 5.6 PySRとの比較は現時点で結論を出せない

PySRは valid_nmse 0.0047–0.0055 と NeSymReS 系より1桁良く、G01 の回復率も noise 0.1 で 0.5 とFT条件（0.0）を上回る。
しかし探索秒数中央値が 8.0 秒 対 3.3–4.2 秒で約2倍であり、有効式率は 0.70–0.79 と低い。
**budgetが統一されていない**ため、この比較から手法の優劣は言えない。これはプロジェクトの未解決課題として既知の項目である。

### 5.7 記録上の不整合

- run直下 `manifest.json` の `status` が `running` のまま。全Phase manifestは `complete` であり、finalize工程が未完了と考えられる。
- `phase4/contributions.json` が全層NaN（§2.3）。主要指標の1つが実質的に欠測している。
- `phase5/hp_selected_main.json` が空、構造holdout版も `val_ce` が NaN。hyperparameterはvalidationで選ばれておらず、固定値が使われたと読むのが妥当である。
- リポジトリのworking treeに未commitの変更が多数残っている。

## 6. 提案

科学的に望ましい案と、本リポジトリで実装可能な案を分けて示す。

### 6.1 本runの範囲で今すぐ実施できること（実装可能）

1. finalize工程を完走させ、`manifest.json` の `status` を `complete` にする。同時に `contributions.json` のNaN原因（全層FT scoreの発散）を、正規化の分母を `max(pretrained, full)` ではなく事前学習単独に変更するか、発散条件を明示的に除外する形で修正する。
2. Phase 4の生scoreに、上限飽和（ablationの $10^{6}$）を区別できるフラグを追加する。現状は「飽和」と「真に大きい」が同じ値になっている。
3. `hp_selected_main.json` が空である事実をREADMEの限界節に明記する。hyperparameter選択を行っていない条件で「validationで選択した」と書かない。
4. 本レポートの §4.2（有理構造の欠落）を、`docs/` の限界節へ一次所見として追加する。

### 6.2 GPU_RUN3の設計に反映すべきこと（科学的に望ましい）

1. **有理式priorへの対応を主課題に格上げする。** 分母を陽に扱う decode 制約（例：$f = P(x)/Q(x)$ の形を強制する2ヘッド decode）、
   あるいは有理式を含むcorpusでの継続事前学習を比較条件に加える。これは本runで最も強い証拠がある方向である。
2. **seed数を増やす。** 現行 n=3 では margin ±0.05 の判定に必要な検出力が無い（§5.3）。
   観測された seed 間ばらつきから、同じ margin で判定するには最低でも n=8–10 が要る。増やせない場合は margin 判定を主結論から外す。
3. **外挿誤差を主要評価軸に昇格させる。** §5.4 の逆転は本runで最も明確な負の所見であり、学習範囲内NMSEだけの報告は誤導的である。
4. **G01を集計から分離する。** 現状 symbolic recovery の全量が線形族由来であり、8族平均は実質「G01の回復率÷8」である。
   族別報告を既定とし、平均値を主指標にしない。
5. 全層FTの有効式率低下（§5.5）は正則化不足の可能性がある。学習率・epoch数のvalidation探索を実際に行った上で再評価する。

### 6.3 本レポートで判断を保留した事項

- DecoderLensの層別差（平均順位 7.79–9.70）が意味のある差かどうか。パース率が0.126と低く、順位の解釈可能性が担保されていない。
- 順位一致における単一層FT順と probe 順の負の関連。層数が7と少なく、`encoder_4`・`encoder_5` の発散が順位を支配している可能性がある。
- noise 0.1 で G01 の回復率がFT条件で 0 になる現象。n=18/セルであり、偶然の範囲かどうかを判定していない。
