# GPU_RUN6 計画（事前登録）：酵素反応速度論の有効法則と ODEFormer の層別解析

- 作成日: 2026-11-18
- 対象モデル: 公開 ODEFormer checkpoint（encoder 4層 dim 256 + decoder 12層 dim 512、
  `assets/odeformer/weights/odeformer.pt`、sha256 `56754040…a5e8`）
- 固定設定: [`configs/gpu_run6/base.yaml`](../../configs/gpu_run6/base.yaml)
- 実行入口: [`scripts/phases/gpu_run6.py`](../../scripts/phases/gpu_run6.py)、共通コード `src/gpu_run6/`
- この文書は確認的評価（seed 1101 系）の実行前に commit して固定する。以後の変更は「改訂」節に追記し、
  変更前の記述は消さない。

## 1. 背景と研究課題

高スループット酵素反応速度論（HT-MEK など）では、変異体ごとに数千〜数十万本の反応進行曲線が得られる。
現状は初速度から Michaelis–Menten（MM）式を当てはめるのが主で、変異体ごとに速度則そのもの
（基質阻害・協同性・可逆性）を選ぶ処理は自動化されていない。NSR は1回の順伝播で式を提案できるため、
この「大量の候補出し」に向くはずだが、NSR は事前学習分布の外で構造回復が弱いことが知られている
（Voigt et al. 2025）。酵素の有効法則は変数を分母に含む有理式であり、ODEFormer の事前学習生成器では
稀な形である。

本キャンペーンの主題は次の2つ。

- **RQ-A（行動）**: 公開 ODEFormer は、酵素反応の有効法則（有理式）の構造を、複雑さをそろえた多項式と比べて
  どれだけ回復できるか。失敗はどの条件（識別可能性・観測変数）に依存するか。
- **RQ-B（層別解析の方法論・主題）**: これまでまとめた層別解析手法
  （logit/tuned lens、対照付き probe、activation patching、block skip、単一層FT、層移植、重み変化量）は、
  それぞれ何を明らかにし、互いに一致するか。有理構造の失敗について、各手法から何が言えるか。

## 2. データ（すべて合成、ODEFormer の正規化座標で直接生成）

時間 t ∈ [1, 10]、100点、初期値1（MM_P は生成物なので0）。公式 `Scaler` が任意の入力を写す座標系と同一なので、
推論は `rescale=False` で行い、下の真の式がそのまま decoder の教師系列になる。

| 族 | 式 | 構造クラス |
| --- | --- | --- |
| MM_S | dx/dt = −V x/(K+x)（基質を観測） | R[1/1] |
| MM_P | dx/dt = V(1−x)/(K+1−x)（生成物を観測＝進行曲線） | R[1/1] |
| SI | dx/dt = −V x/(K+x+x²/Ki)（基質阻害） | R[1/2] |
| HILL2 | dx/dt = −V x²/(K+x²)（協同性 n=2） | R[2/2] |
| LIN | dx/dt = −a x | P[1] |
| QUAD | dx/dt = −a x + b x² | P[2] |
| QUAD2 | dx/dt = −a x − b x² | P[2] |
| MA_SC | E+S⇌C→E+P を (s, y=c/e0) で観測（2次多項式・2次元） | 単項式の台 {s, sy, y} |
| MA_S | 同じ質量作用系を s だけで観測（QSSA の有効法則＝MM） | R[1/1] |

- K は対数一様 [0.03, 30]、終端の残存率は一様 [0.05, 0.4]、速度定数はそれに合わせて較正する。
- 構造クラスは sympy で約分した分子・分母の次数で判定する（パラメータ化に依存しない）。係数が最大係数の
  1e-4 未満の項は除く。

## 3. 指標

- **class_in_beam**（主指標）: beam 50候補のいずれかが真の構造クラスに一致する割合。
- **selected_class_match**: 入力軌道の再構成 R² 最大の候補（公式 API の選択）がクラス一致する割合。
- **recon_r2**: 選択候補の入力軌道の再構成 R²。**gen_r2_min**: 未使用初期値（0.6, 1.2。MM_P は 0.3）での最小 R²。
- 層別指標は §5 に記す。

## 4. 仮説と判定基準

統計は問題単位のブートストラップ（2,000回、percentile 95% CI）。モデルの seed は1つであり、
結論は「この checkpoint・このデータ生成条件」に限定する。

- **H1（構造の欠損）**: 有理式4族の class_in_beam の平均は、多項式3族より低い。
  差の 95% CI 上限が 0 未満、かつ差が −0.3 以下なら支持。
- **H2（数値フィットが構造の失敗を隠す）**: 有理式族でクラス不一致となった選択候補の recon_r2 の中央値は 0.99 以上。
  満たせば支持。補助として、クラス一致時と不一致時の gen_r2_min を比べる（記述）。
- **H3（識別可能性）**: MM_S で、K ∈ [0.1, 3] の class_in_beam は K < 0.1 または K > 3 より高い。
  差の 95% CI 下限が 0 超なら支持。
- **H4（観測変数、探索的・両側）**: 中間体を観測した MA_SC（多項式）と、基質だけの MA_S（有理式）で回復率を比べる。
  予備観察では MA_SC は硬い（stiff）2次元系のため回復しなかったので、方向は事前に決めない。
- **H5（情報はあるが出力されない）**: decoder の位置0（教師 token を見る前）の状態から、有理/多項式の2値を
  ロジスティック回帰 probe で判別できる。いずれかの decoder 層で、正解率が
  (a) ラベル置換対照より 0.2 以上高く、(b) 入力統計量ベースライン −0.05 以上なら支持。
  H1 と同時に支持されれば「情報は表現にあるが、生成で使われない」と解釈する。
  補助として MM_S の log K を ridge 回帰で予測する（R²）。
- **H6（tuned lens、記述的）**: 有理式の教師系列で、`inv` token の tuned lens 順位が、いずれかの decoder 層で
  10位以内に入るかを報告する（「途中で候補に上がり、最後に捨てられる」か「最初から考慮されない」か）。
  logit lens は語彙 10,293 に対し初期層の分布がほぼ平坦になるため、対数確率ではなく順位で読む。
- **H7（patching、記述的）**: 有理式入力（clean）と多項式入力（corrupt）を入れ替えたときの、有理式の教師系列の
  対数尤度差（clean − corrupt）を報告する。差が 1 nat を超える組に限り、層ごとの回復率
  （patched − corrupt）/（clean − corrupt）を報告する。相手は軌道が最も近い QUAD（最小対）と無作為の QUAD の2種類。
- **H8（適応）**: MM_S・SI・HILL2 の訓練問題（seed 1303、各200）で全層FTすると、
  (a) 訓練族の未使用パラメータの評価問題で class_in_beam が上がり、
  (b) 未学習族 MM_P・MA_S にも転移し、
  (c) 多項式対照の回復率と一般生成器問題の CE は悪化しうる（忘却、両側）。
  (a) は 95% CI 下限が 0 超で支持。(b)(c) は記述。
- **H9（手法間の一致、主題）**: 層ごとの重要度を各手法から作る。
  probe 正解率（有理/多項式）、tuned lens の教師 token 対数確率の層間増分（有理式族）、patching 回復率、
  block skip による教師系列の対数尤度低下、単一層FTによる有理式訓練族の教師強制 CE の低下量、
  層移植（基礎モデルへ移植）による同 CE の低下量、重み変化量（全層FT 後の相対フロベニウスノルム）。
  これらの順位相関（Spearman）の多数が |ρ| < 0.5 なら「手法は別のものを測っている」を支持。
  GPU_RUN5 の横断表（読み出せる・壊すと悪化・更新で改善は不一致）からの予測である。

## 5. 層別解析の手順

- 層の単位は block 出力（post-LN の `layer_norm2[i]`）。encoder 4、decoder 12。
- **logit / tuned lens**: 教師強制で各 decoder 層の状態を最終射影に通す。tuned lens は層ごとのアフィン変換
  （恒等初期化）を、公式生成器の一般問題（seed 1505、1,500問、8 epoch）で最終層分布への KL 最小化で学習する。
  評価データは使わない。
- **probe**: encoder は入力点で平均、decoder は位置0の状態。訓練は seed 1202（各族80）、評価は seed 1101。
  対照はラベル置換と入力統計量（x, dx/dt, d²x/dt², 相対速度の分位点）。
- **block skip**: decoder block l の出力を入力で置き換える（その block を飛ばす）。各族の最初の20問。
- **patching**: 1つの block 出力を clean 実行の値で上書きする。shape が合わない場合はエラーで止め、
  平均化や broadcast をしない。同一入力で自分の活性化を戻すと出力が一致することを確認する。
- **単一層FT と層移植**: Adam、lr 1e-4、400 step × batch 8、seed 0。単一 block だけを学習した条件を16個、
  全層FT から1 block だけ基礎モデルへ移す条件と、全層FT モデルから1 block だけ基礎に戻す条件を各16個。
  学習率の感度は lr 3e-5 で全層FT と3つの単一層条件だけを確認する。
  評価は教師強制の CE と `inv` 対数確率（各族30問）と、beam（各族12問）。

## 6. 予備観察（事前登録前に見たもの）

- seed 1 の MM_S 1問で、教師強制の `inv` 対数確率を logit lens で見た。初期層で約 −7、最終層で約 −32。
- smoke run `gpu_run6_smoke`（seed 101–707 の縮小版）で全 phase を通した。行動評価では
  多項式族の class_in_beam が 0.87–1.0、有理式族が 0–0.27、MA_SC が 0 だった。
  tuned lens（学習不足）は `inv` を全層で −20 以下とした。matched patching の clean−corrupt 差は平均 1.4 nats。
- これらは H1・H4・H6・H7 の設計に影響した。そのため確認的評価は、smoke で一度も見ていない seed（1101 系）で行う。
